PDF → Markdown 转换器

将 PDF 每页渲染为图像，通过视觉语言模型（VLM）结构化提取内容。串行 Phase 1 建立全文标题体系，并行 Phase 2 转换正文，最终经 20 遍确定性规则管道输出干净的 Markdown。

PDF 渲染
01
render_pdf_to_images() · pdf_extractor.py
用 PyMuPDF（fitz）将 PDF 每页栅格化为 PNG 图像，写入 _debug/pages_img/。同一批图像同时供 Phase 1 和 Phase 2 复用，无需重复 IO。DPI 越高 VLM 识别率越好，但处理时间和内存线性增加。
PDF_RENDER_DPI=600 # A4 → 约 4960×7016 px，推荐 PDF_RENDER_DPI=300 # 速度快约 4×，适合草稿验证
Phase 1 · 串行 结构提取 — run_phase1()
01
extract_page_structure_vlm() — VLM 逐页串行分析
每页传入图像 + 文件标题 + 页码 + previous_page_tail（前页结构摘要）+ 当前标题栈，调用 VLM 输出 JSON。JSON 解析为 PageStructure，包含标题列表、目录页/附件页/跨页表格标记。visual_prominence=normal 且 confidence < 0.80 的条目视为正文编号误判，直接过滤。随后调用 enrich_page_structure() 用 PDF 文本层补充修正，再检测流程图页漏报并从文本层恢复标题。
# VLM 每页输出（JSON） { "page_no": 3, "is_toc_page": false, "is_table_continuation": false, "headings": [ { "text": "二、原材料要求", "level": 2, "confidence": 0.95, "visual_prominence": "high" }, { "text": "2.1 钢材规格", "level": 3, "confidence": 0.92, "visual_prominence": "high" }, { "text": "1. 检验合格", "level": 3, "confidence": 0.61, "visual_prominence": "normal" } // ↑ confidence=0.61 < 0.80 且 normal → 过滤掉 ], "table_titles": [{ "text": "表 2-1 钢材尺寸规格" }] }
02
update_heading_stack() — 累积标题栈
每页 VLM 分析后立即更新累积标题栈，传给下一页 VLM 的 current_heading_stack 参数，使 VLM 知道当前处于文档哪一层级。算法：新标题入栈前弹出所有层级 ≥ 新标题的旧条目，再 push 新标题（浅层标题覆盖深层）。
# 示例：标题栈变化 # 栈初始：[H2 一、总则, H3 1.1 适用范围] # 新标题：H2 二、原材料要求 # 步骤：弹出 H3（level≥2），弹出 H2（level≥2），push 新 H2 # 栈结果：[H2 二、原材料要求]
03
normalize_global_headings() → phase1_canonical
所有页分析完毕后，VLM 可能对同一标题在不同页输出不同层级（如第 3 页 ## 二、第 7 页 ### 二）。遍历所有 PageStructure，以归一化文本（去数字、去标点）为 key，记录全文最小层级，输出 phase1_canonical 字典，供后处理最终 Pass 使用。
# phase1_canonical 示例 { "二原材料要求": 2, # 全文最小层级 H2 "钢材规格": 3, "检验方法": 3, "附件": 2, } # normalize_markdown_heading_levels() 用此字典重写最终输出
04
relevel_headings_with_llm() — Phase 1.5：LLM 全局层级修正
Phase 1 逐页提取的最大缺陷：每页 VLM 只看当前页，无法知晓整篇文档的层级全貌，导致同类标题（如工序章节的附表）在不同页被赋予不同层级。此步骤在全部 PageStructure 生成后、precompute 之前，将所有标题序列化为纯文本 JSON，单次调用 LLM（无图片、无并行），从全局视角统一修正 level 字段。

修正策略：① 同类工序章节（G01…G15 等）强制平级；② 附表/附件降为所属章节 level+1；③ 正文小节（本工序要点：等）降为所属章节 level+1。修正结果直接写回 Heading.level，后续 precompute_page_contexts 和 Phase 2 使用修正后的层级。

容错：LLM 输出条目数不符、text/page 不匹配、level 越界时均保留原值；LLM 调用失败则静默跳过，整体流程不中断。设置 ENABLE_RELEVEL=false 可完全跳过此步骤。
# 输入（所有非目录页标题，纯 JSON，无图片） { "file_title": "NPD2426工艺文件", "headings": [ {"page": 16, "text": "G02 瓷浆精炼工序工艺规程", "level": 2}, {"page": 25, "text": "附表 1 ...配方表", "level": 2}, // ← 误置，应为 3 {"page": 31, "text": "G03 涂布工序工艺规程", "level": 2}, ... ] } # LLM 输出（只改 level，不改 text/page） [ {"page": 16, "text": "G02 瓷浆精炼工序工艺规程", "level": 2}, {"page": 25, "text": "附表 1 ...配方表", "level": 3}, // ← 修正 {"page": 31, "text": "G03 涂布工序工艺规程", "level": 2}, ... ]
05
precompute_page_contexts() → PageContext × N
重放标题栈算法（与上面 update_heading_stack 相同逻辑），从头到尾模拟文档遍历，为每页快照正确的标题路径。若不预算而让 Phase 2 直接用 Phase 1 末页的标题栈，所有页面都会共用同一错误的标题上下文。
# 为何需要预算 # Phase 2 是并行的，无法保证执行顺序 # 必须在 Phase 1 结束后串行预算每页的 PageContext # 这样第 3 页用第 2 页结束时的标题栈，而非第 50 页的 contexts = precompute_page_contexts(document_context, page_raw_texts) # contexts[3].current_heading_stack → 第 3 页开始时的正确标题路径
Phase 2 · 并行 内容转换 — _run_phase2_parallel()
01
convert_page_to_markdown() × N — ThreadPoolExecutor 并行
每个线程接收页面图像 + 预算好的 PageContext（含标题栈、前驱尾段、是否流程图页等），调用 VLM 输出该页完整 Markdown。PageContext 已包含所有必要上下文，各页之间无数据依赖，可完全并行。任一页 VLM 调用失败时结果保留空串，不中断其余页面。
with ThreadPoolExecutor(max_workers=16) as pool: futures = {pool.submit(convert_one, p): p for p in range(1, total_pages + 1)} for f in as_completed(futures): pno = futures[f] try: page_no, md = f.result() results[page_no] = md except Exception: pass # results[pno] 保持空串，不中断
02
repair_tail_continuations() — 跨页续接修复
Phase 2 并行时每页用 Phase 1 的结构摘要作为前驱尾段（非真实文本），可能造成两类续接错误：① 跨页表格断裂（上页末行是 |，当前页首行也是 | 但第二行不是分隔行）；② 语句截断（当前页首行以小写字母或中文逗号开头）。对命中的页，提取上一页真实 Markdown 末尾 300 字符，创建新 PageContext 副本并重跑 VLM。
# 续接检测逻辑 prev_ends_table = prev_lines[-1].startswith('|') curr_mid_table = (curr_lines[0].startswith('|') and not is_separator(curr_lines[1])) curr_mid_sentence = re.match(r'^[a-z，。、；：]', curr_lines[0]) if (prev_ends_table and curr_mid_table) or curr_mid_sentence: real_tail = extract_tail_text(results[n-1], max_chars=300) ctx = dataclasses.replace(contexts[n], previous_page_tail=real_tail) results[n] = convert_page_to_markdown(images[n], ctx)

01
20 遍顺序规则管道 · postprocess.py
20 遍确定性正则规则，无 VLM 调用，顺序执行。每遍接收上一遍的输出，以 phase1_canonical 为标题层级锚点修正 Phase 2 的随机偏差。各 Pass 的功能和顺序见第 03 节后处理管道。
# 典型修正：标题层级归一化 # Before — 同一标题在不同页被 VLM 输出为不同层级 ### 二、原材料要求 # 第 3 页 ## 二、原材料要求 # 第 7 页 # After — phase1_canonical 锚定 H2，全文统一 ## 二、原材料要求 ## 二、原材料要求 # 典型修正：连续编号标题降为有序列表（≥4 条） # Before ## 1. 检查外观 ## 2. 测量尺寸 ## 3. 核对标识 ## 4. 填写记录 # After 1. 检查外观 2. 测量尺寸 3. 核对标识 4. 填写记录
02
validate_markdown() + repair_markdown()
最终校验层。validate_markdown() 扫描输出 Markdown 的结构错误（如未闭合的 HTML 标签、缺失表头等），返回 ValidationReport。若 report.has_errors 为真，则调用 repair_markdown() 按报告内容补救，确保输出文件是合法的 Markdown。

02

两阶段 VLM 调用

PHASE 1 · outline.py · 串行

结构提取

逐页串行调用 VLM，只提取结构元数据，不输出正文内容。每页的结构摘要作为 previous_page_tail 传给下一页，保持跨页上下文连贯。

  • 输出每页 JSON：标题列表、目录页、附件页、跨页表格标记
  • VLM 返回 visual_prominence + confidence 双重置信度
  • confidence < 0.80 且 prominence=normal 的条目直接过滤
  • 流程图页 VLM 漏报时，从 PDF 文本层恢复标题（兜底）
  • 完成后全局归一化标题层级，输出 phase1_canonical
  • Phase 1.5：单次 LLM 文本调用（无图片），全局修正层级混乱的附表/附件和正文小节；失败时静默回退
PHASE 2 · convert_page.py · 并行

内容转换

用 Phase 1 预算好的 PageContext（含标题栈、前驱尾段）并行批量调用 VLM，每页独立输出完整 Markdown，页面间无依赖。

  • precompute_page_contexts 为每页预算正确的前驱标题栈
  • ThreadPoolExecutor，最多 PHASE2_MAX_WORKERS（默认 16）并发
  • 任一页失败保留空串，不中断其余页面
  • 检测跨页表格断裂 / 小写开头误续行
  • 对问题页用真实前驱尾段重跑（repair_tail_continuations）
文档表格 → HTML <table>

PDF 原文中的简单表格、复杂表格、跨页续表统一输出 HTML 表格

流程图辅助结构

Mermaid 图和节点列表等生成型辅助结构不属于 PDF 原文文档表格
